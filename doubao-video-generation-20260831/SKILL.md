# 视频提示词反推与人物一致性生成

适用于用户提供参考视频和人物图片，并要求反推动作提示词、将提示词中的人物替换为图片角色，或在豆包生成视频的任务。参考视频只用于 Codex 观察和提示词反推，不上传到豆包；豆包生成时只上传人物图片。

## 前置流程

1. 用户明确要求打开网页或生成视频时，按目标账号使用 Chrome“用户1”或“用户2”配置，不使用应用内浏览器的环境状态替代 Chrome。
2. 目标为账号1时，检查并连接 Chrome“用户1”；目标为账号2时，检查并连接 Chrome“用户2”。若目标 Chrome 用户窗口未打开，先由 Codex 负责启动或切换到对应的 Chrome 用户配置，再打开豆包，不要求用户手动准备窗口。只有在系统无法启动、切换或连接对应 Chrome 用户时才停止并报告阻塞。
3. 在对应 Chrome 用户中打开 `https://www.doubao.com/chat/`；若已有当天目标账号的豆包专用对话则按当天规则使用，否则新建当天专用对话。
4. 页面加载后确认当前页面为豆包，且账号标识与目标一致（用户1对应“账号1”，用户2对应“账号2”）；若未登录、账号不符或 Chrome 连接不可用，停止网页操作并告知用户。
5. 完成上述页面确认后，再读取参考视频、反推动作提示词、上传唯一人物图片并执行生成流程。

## 反推规则

1. 先读取视频元数据（时长、宽高、帧率），再按动作变化提取关键帧；不要声称找回原作者的逐字原提示词，只描述可观察到的视觉内容。
2. 提示词必须明确写出：视频时长、画幅（通常 9:16）、场景、光线、镜头运动、主体位置和景别。
3. 把动作写成带时间范围的连续时间轴。每段至少包含时间、景别、动作和镜头行为；时间段总和应接近视频时长。
4. 动作描述应包含起始姿态、重心变化、关键动作、结束姿态，以及头发/衣摆/道具的运动连续性。
5. 若替换为人物图片，先删除或改写提示词中原参考视频人物的外貌、服装和身份描述，再以用户上传的人物图片作为唯一人物参考。提示词必须加入身份锁定约束：脸部、五官、发型、发色、服装、配饰、体型比例、画风以图片为准且保持不变。只替换人物，不改变参考视频反推出的动作、节奏、镜头和环境要求，除非用户另有说明。
6. 负面提示词覆盖变脸、换装、多人、额外肢体、肢体畸变、出画、道具消失、卡顿、画面撕裂、字幕、文字和水印；按场景补充具体风险（例如杯子掉落或液体洒出）。

## 豆包/Chrome 执行规则

- 只有用户明确要求生成时才进行上传、提交或确认；固定使用两个 Chrome 豆包账号：账号1使用 Chrome“用户1”配置，账号2使用 Chrome“账号2”配置。
- 生成时只向豆包上传用户提供的人物图片；参考视频严禁上传，仅在本地读取元数据、抽取关键帧并由 Codex 反推动作、节奏、镜头和环境提示词。不得把参考视频作为豆包附件或视频参考素材。
- 不使用“+”号文件选择器上传。使用已验证的图片粘贴方式上传人物图片；粘贴后检查附件数量，网页可能把一次粘贴显示为两个相同缩略图，必须删除多余缩略图并确认最终只剩一张图片附件。
- 账号1和账号2分别执行生成流程，账号、对话、额度、任务状态和结果必须独立记录；但两个账号的流程允许同时执行，可以并行提交、等待生成和分别下载，不必等一个账号完成后再开始另一个账号。每个账号的目标是累计成功生成 3 个视频。先为该账号提交 3 个独立生成任务，并等待结果；即使其中已有任务成功，也继续保留其余任务并提交到初始 3 个任务完成。若有任务明确失败，则在该账号仍有额度时补提交，直到累计成功 3 个视频，或明确遇到额度不足/平台拦截。生成中的任务不得重复提交；成功任务本身不重复提交，但成功数量不足 3 个时可以提交新的补足任务。两个账号均达到 3 个成功视频，或明确因额度不足/平台拦截停止后，才结束整体流程。
- 每个自然日开始时，为每个账号新建一个当天专用的豆包对话，并记录该对话；该账号当天的 3 个视频必须全部在这个新对话中生成，不得混用旧对话或另开当天的其他对话。当天先在该对话中提交 3 个独立生成任务，允许多个任务并行生成；哪个任务先成功，就立即下载并核验哪个视频，下载过程不得阻塞其他任务的生成，也不要求下载完成后才提交或等待下一个任务。不得等该账号的多个任务全部完成后才统一下载。已生成的视频下载成功后才计入本地交付记录；下载失败应在不重复提交生成任务的前提下优先重试下载。
- 生成前核对模型、时长和图片数量；图片数量应为 1，且附件类型为人物图片。把实际使用的模型告知用户。不得臆造“免费”；以页面标注为准。
- 豆包出现安全确认时，仅在用户已明确授权本次生成且素材用途未改变的情况下确认；不得用改写规避平台审核。
- 若平台明确显示额度用尽或其他不可继续提交的拦截，记录原文和是否扣除额度，停止该账号后续提交。若返回“疑似侵权/违规，生成额度未扣除”或同等含义的提示，该次不计入成功数量，也不视为额度耗尽；在不改写提示词或素材来规避平台审核的前提下，继续补提交新的生成任务，直到该账号累计成功 3 个视频。若同一账号连续 10 次收到相同的侵权/违规拦截，则视为明确的平台拦截并停止，避免无限提交。明确的技术失败或生成失败同样可补提交，直到该账号累计成功 3 个视频；不得在没有失败或成功数量缺口时额外提交。
- 每个账号的额度判定必须同时满足：对话框中没有仍在生成的视频任务；再次在“视频生成”模式提交时明确显示该账号次数用完；并结合页面显示的扣除/返还结果判断。单次审核失败、侵权拦截或显示额度未扣除，都说明额度可能已返还，不应直接判定该账号额度耗尽。
- 只要页面没有明确提示该账号额度或次数已经用完，且该账号累计成功数量仍不足 3 个，就可以继续补提交新的生成任务；已有任务仍在生成时不得把同一任务重复提交，但其他独立补足任务可按当日并行规则提交。
- 生成耗时较长时，告知“已提交/生成中”，不要把提交误报为已完成；如用户要求监控，再设置可停止的定时检查。

## 生成视频下载规则

- 只有用户明确要求下载时才下载；下载前确认当前页面仍是对应的豆包账号和视频结果卡片。
- 优先从视频结果卡片的下载按钮保存原始文件；若按钮不可用，再从页面可见的视频元素或其 source 地址取得文件。不得把海报图当成视频。
- 下载完成后用视频元数据确认文件可播放、时长和分辨率正常，并按“账号_日期_序号.mp4”命名。
- 所有下载并核验成功的视频必须归档到当前项目文件夹下以当天日期命名的文件夹中，文件夹格式为 `YYYY-MM-DD`；同一天账号1和账号2的结果放在这个同一日期文件夹中。浏览器下载目录中的原始视频继续保留，不覆盖原文件。发现多个结果时逐一核对去重，不能只凭缩略图数量推断视频数量。

## 豆包水印动态遮盖规则

- 仅在用户明确要求处理水印时执行，并始终保留原始视频，输出另一个带后缀的文件（例如 `_CV精准动态虚化.mp4`）。
- 水印位置可能随时间在画面不同边缘或角落移动，不能使用单一固定大矩形，也不能只检测底部区域。
- 先从原视频抽取包含“豆包AI生成”字样的清晰帧，裁剪出只含文字的模板，尽量排除地面、建筑和人物等背景；模板路径含中文时，复制到 ASCII 临时路径供 OpenCV 读取。
- 逐帧在全画面做模板/边缘匹配，保留多个彼此分离的高匹配候选点，以应对水印跳位和单个最强匹配落在背景纹理上的情况。对每个候选点只扩展少量边距，形成紧贴文字的小框。
- 对小框使用足够强的高斯模糊，使文字不可辨认；不要模糊整条底边或大面积背景。输出时保留原音频、帧率、画幅和时长。
- 处理后必须抽取开头、中段、结尾及动作快速变化处的多帧复核：检查水印是否仍可读、是否漏检、是否误伤人物脸部/主体。若漏检，调整模板裁剪、匹配阈值或候选数量后重新处理。
- 最终报告原始文件和遮盖后文件分别在哪里，并说明已进行动态位置复核；无法确认完全遮盖时要如实说明，不得声称“已全部去除”。
- 若全画面模板匹配在快速运动、复杂背景或低对比度画面中漏检，必须先暂停批量处理，改用人工复核得到的“按时间段锁定角落/边缘 + 小范围高斯模糊”作为兜底；每个时间段只遮盖实际出现水印的紧凑区域，切换前后保留短暂重叠并再次抽帧检查。第一条视频应先单独测试，确认遮挡效果合格后才能继续处理后续视频。

## 处理后文件保存规则

- 水印处理完成后，不能覆盖原始视频；带 `_CV精准动态虚化` 后缀的处理结果先写入当前日期文件夹。
- 将已经复核合格的所有处理后视频统一移动到当前项目文件夹下的 `YYYY-MM-DD\处理完毕` 文件夹；文件夹不存在时创建。账号1和账号2当天的处理结果放在同一个日期的“处理完毕”文件夹中。
- 移动前逐一确认文件可播放、时长/分辨率正常且音频存在；移动后保留原始视频在日期文件夹中，不覆盖原始下载文件，也不要把测试截图、模板或失败版本放入“处理完毕”。
- 最终报告“处理完毕”文件夹的完整路径、已归档的视频数量和文件名；若只处理了部分视频，明确列出未处理的视频。

## 输出格式

先给出结论：这是基于画面重构的提示词，不是原始提示词。随后提供一份可直接复制的完整提示词，按“角色一致性、视频规格、分段时间轴/景别、动作与物理、负面提示词”组织。若执行了网页生成，最后报告账号、模型、图片数量和当前状态。
